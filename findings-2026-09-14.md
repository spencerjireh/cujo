## 1. What each check costs

Over the nine runs of rounds one to three, per thread (round four, read
separately, sits inside the same ranges):

| thread | runs | median tokens | p90 | share of all tokens | USD per run |
| --- | --- | --- | --- | --- | --- |
| main | 9 | 409k | 454k | 48.7% | 0.040 |
| smoke | 10 | 126k | 342k | 20.0% | 0.012 |
| probes | 8 | 102k | 259k | 17.3% | 0.013 |
| tests | 9 | 87k | 112k | 11.0% | 0.008 |
| detonation | 3 | 76k | 81k | 3.1% | 0.010 |

The parent is half the run. The three check sub-agents together are the other
half, and they exist to wrap one `sniff.py run` each and hand back a report.
`smoke` is the most expensive check and the most variable (p90 nearly three
times the median); on #45 round two its first head run was superseded after
proxy artifacts and rerun.

A fixture run costs 5 to 11 cents. A sandbox run of a change to this monorepo
costs 16 cents. The decision rule in track 6 said: under about 1 USD,
efficiency work targets precision and not tokens. That holds by an order of
magnitude. Track 7 is still worth doing, for latency and predictability and
because half the tokens are a model doing a shell script's work, but cost is
not the reason.

Where the time goes is a different story. Setup, from turn start to the first
check, ranged from 20 s to 4.4 min on the same repository (`setup.ms` per run:
20 s, 46 s, 79 s, 85 s, 93 s, 104 s, 106 s, 172 s, 266 s). That is the
sandbox install and the parent's reading, and it varies by a factor of ten
for the same tree. Provider latency, not work, is the likely variable.

On the regression, with the per-call limit raised to 300 s, OCR posted three
comments on `pricing.py`: a `high bug` that names the half-cent tie case
exactly ("1.005 rounds to 1.01 under HALF_UP but 1.00 under HALF_EVEN" and
that this contradicts the stated goal of matching the accounting export); a

implementations. All three are true. The first is the planted regression found
by reading alone, without a test; the second is what Cujo's `probes` found in
round four; the third is something no Cujo check looked at.

Against the decision rule, "OCR's acceptance at or above diff mode's at fewer
tokens": on the fixture OCR's acceptance is 3 of 3 acted, at 68k tokens and
1.5 cents. Diff mode did not run on the fixture (a manifest floor or a
sandbox default put every fixture run in the sandbox), so the like-for-like
comparison is not in this file; the nearest is diff mode on cujo's own pull
requests today, 25k to 85k tokens each with no findings above `info` on
changes that had none to find. What this day does establish:

- OCR reads a single-file regression as well as the sandbox proves it, and
  says why in a way the test failure does not.
- OCR does not look at manifests. The dependency half of Cujo has no overlap
  with it at all.
- OCR on this model is slow and provider-bound: 13 s to 9 minutes for one
  file, and one run in four lost to a stalled model call. The sidecar's
  per-call timeout is 300 s now.
- Its output is a list of positioned comments with severity and category, the
  same shape as Cujo's findings, so posting it under the review would be a
  renderer change and not a design change.

The rule is not decided on one regression and three docstrings. What would
decide it: the week's real pull requests with diff mode and OCR on the same
heads, tallied the same way.

## 5. Things the day found that were not measurements

- **The sidecar's first deploy took the stack down.** It exited at boot for
  lack of model settings; Coolify read one exited service as the application
  having exited and Traefik answered 503 for the board. Fixed in #152: it
  boots unconfigured and refuses with 503.
- **A merge to `main` kills every run in flight**, because the deploy
  restarts the harness. Run `1aa7d7e0` died to the #150 merge.
- **`/cujo review` on a head the session had reviewed produced no review**:
  the model read its earlier review in the history and declined to post twice
  (decision 150, #153).
- **Node's fetch gives up after five minutes of headers**, whatever the
  caller's signal says. Two of the first three fixture runs lost their OCR row
  to it (#154, start-then-poll).
- **The 30 minute ceiling is a function of repository size.** A change to
  this monorepo needs 12 minutes to install and 15 to test in the box. At the
  new 15 minute ceiling, orders-api runs finish with 4 to 9 minutes to spare
  and one run lost its review to a provider retry on `smoke`.
- **A git dependency on `github.com` cannot always be fetched from the box.**
  The egress gateway answered `502` to pip's `CONNECT github.com:443` on one
  run and let it through on the next. The clone host is meant to be allowed.
- **The provider is the variable.** One `smoke` thread failed on
  `tool_output_invalid` from an upstream provider and was respawned; setup
  time varies tenfold on the same tree; the sidecar's `ocr` took 13 s on one
  #45 run and over 300 s on the next with the same model.

## What the numbers decide

- **Cost:** under 1 USD by an order of magnitude. Track 7 proceeds for
  latency and predictability, not cost. Precision work is first.
- **Probes:** never found what `tests` did not, on this fixture. Track 7 makes
  `probes` off by default and lets the parent turn it on with the coverage map
  in hand. Revisit with an agent-written PR whose tests pass by construction.
- **OCR against diff mode:** undecided on the fixture, and leaning toward OCR
  as the reader: it found the regression by reading, at 1.5 cents, and its
  output is the same shape as a finding. Decided by the week's real pull
  requests on the same heads.

## 19. The #176 deploy took the site down (2026-09-16 14:40-15:35)

Merging #176 deployed 3cf84c8; the cujo container exited on its first
line with `Dynamic require of "process" is not supported` and the app

failed at the healthcheck; the read API answered 503 for about 55 min.

Cause: `yaml` (new in #176, for `.cujo.yml`) is CommonJS, and
`apps/cujo/tsup.config.ts` bundles every dependency into one ESM file
where esbuild's shim throws for a dynamic require. Nothing ran the
artifact: tests import source, `pnpm build` only produces a file, the
docker job built an image it never started. Found by running the locally
built image, which reproduced it in one command.

Fix #185: a `createRequire` banner on the cujo bundle, and a CI step that
starts every image it builds with no configuration and fails on a module
error. The first spelling of that step used `timeout 60 docker run` in
the foreground and hung the ocr-sidecar job for 20 min (timeout signals
the client, the client hands it to a container that ignores it); the
second runs detached and reads the log. Merged with --admin, because
`cujo/guard` is a required context and Cujo was the service that was
down. #186 adds decision 168.
